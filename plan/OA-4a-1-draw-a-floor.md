## 3. How

**3.1 Canvas: DESIGN CHOICE DC-P2.** `FlutterMap(MapOptions(crs: CrsSimple(), minZoom, maxZoom, interactionOptions: only scrollWheelZoom))` supplies the camera and wheel zoom at the pointer; **one** custom child layer, a `CustomPainter` driven by `MapCamera.of(context)`, draws the whole active level from a pure `scene.dart` (document + camera to draw operations), and all hit-testing and handles work in metres through `projection.dart`. *Checked in flutter_map 8.3.2's source (pub cache):* `CrsSimple` is transformation (1, 0, −1, 0) over a lon/lat projection (`crs.dart` 138-149), so the screen y runs down as `-lat`; `scale(zoom) = 256 · 2^zoom` (`crs.dart` 64), so 4 to 400 pixels per metre is a zoom of about −6 to 0.64, computed from the constants, never written; `MapCamera.of`, `latLngToScreenOffset`, `screenOffsetToLatLng` exist (`camera.dart` 123, 337, 353); `InteractiveFlag.scrollWheelZoom` and `MapOptions.minZoom/maxZoom` exist; `flutter_map.dart` does **not** re-export `LatLng`, so `latlong2` is a direct dependency (pin 0.10.1 from the cache, RECALLED as current; its range in flutter_map's pubspec is `>=0.9.1 <0.11.0`). `projection.dart` holds the three conventions (metre unit; x right, z down so `lat = -z`; rotation 0 faces −z, clockwise positive) and is tested alone. Primary drag belongs to the tools, so flutter_map's own drag is off; a `Listener` (`pointer_router.dart`) sends the right and middle buttons to `MapController.move` (pan). Draw order bottom to top: floor and grid, site and footprint outlines, units, walls, openings, selection, handles, snap marker. **Hit order (AC-62, written here):** a handle of the selection, an opening, a wall, then a unit (the smallest area first, so an inner unit wins); 4a-2 inserts its kinds above units. *Alternative:* flutter_map's `PolygonLayer`/`PolylineLayer` with `hitNotifier` (checked present, `layer_hit_notifier.dart`): less code for the first demo, but one `Polygon` and a `List<LatLng>` per element is allocation-heavy at the 300 units + 2,000 walls + 2,000 openings a level may hold, and the vertex, edge and snap handles need own hit tests anyway. *Second alternative:* no flutter_map, `InteractiveViewer` and a painter: fewer packages, but E-04 and AC-60 name flutter_map.

**3.2 Model and undo (DC-E10; DC-P3).** Immutable typed classes for what 4a-1 edits (document, site, building, level, floor, wall, opening, unit); every other field of those, and every element kind not drawn yet (items, corrections, points, connectors, `backdrop`, `georeference`), is kept untouched in a `rest` map or a `RawElement`, so AC-76's "nothing dropped, same order" holds by construction and 4a-2 and 4a-4 type their kinds when they edit them. *Alternative:* a persistent JSON tree with typed views: less typing now, more casting everywhere. A change copies the **one** list it touches (copy on write: one level's `walls`, at most 2,000 references, about 16 KB, RECALLED estimate) and shares every other list, level and element, so 100 snapshots hold only what changed. The stack keeps up to `UNDO_STEPS_MAX` documents plus a redo list. `beginGesture()` stores the snapshot; the document is replaced live; `endGesture()` commits one step if the document is no longer identical, else drops it (AC-69). A typed field change is one step, and keystrokes in one field of one element within one autosave debounce coalesce into it (**DC-P4**; *alternative:* commit on blur only, so the canvas lags the panel, which AC-66 forbids). Reload, a blank start and a failed-then-reloaded draft reset the stack. The measured memory is AC-98 in 4a-3; 4a-1 ships a `stats` read (snapshot count, shared-element count) for it and a test that untouched levels stay `identical()` across 100 steps.

**3.3 Autosave (AC-70 to AC-72; DC-E8, DC-E9).** `autosave_controller.dart`, with an injectable clock; `revision` counts document replacements, "dirty" is `revision != lastSentRevision`.

| State | Event | Next | Action |
|---|---|---|---|
| none, saved, dirty, error | change | dirty | restart the 1.5 s timer (`AUTOSAVE_DEBOUNCE`) |
| any but saving, conflict | structural action (blank start, add floor, later restore, clear, import) | saving | cancel the timer, save now |
| dirty, error | timer, or "Try again" | saving | `PUT {layout, baseVersion}`; only one in flight |
| saving | change | saving | remember the revision moved |
| saving | 200 | saved (dirty again if the revision moved, timer re-armed) | `baseVersion = draftVersion` of the answer; store `updatedAt` |
| saving | 409 | **conflict** | stop all saving; never retry, never merge; tools, panels and Publish disabled |
| saving | 400 with `problems` | error | list at most 20 with the total; a click selects the element the path names (`levels[i].units[j]…` resolved in the model; a backdrop path selects the level) |
| saving | other failure (offline, 5xx, 413) | error | `formatApiError`; the drawing stays; no timer retry |
| conflict | Reload, after a confirm (default Cancel) | none | `GET …/map`, replace the document, reset undo |

Blank start sends `baseVersion` = the loaded `draftVersion` (0 for no row; OA-2's first save takes `0`). The bar shows words and an icon for each state, never colour alone. **Leaving (AC-73):** `GoRoute.onExit` (present in go_router 18.0.2, `route.dart` 285; its behaviour inside the admin `ShellRoute` is RECALLED and the route-change test checks it) first awaits pending and running saves, then asks Stay (default) or Leave without saving in error or conflict. Closing the tab: a `beforeunload` handler through `package:web` (`onbeforeunload` exists in web 1.1.1, `html.dart` 1672). **Best-effort save: DESIGN CHOICE DC-P6.** A `fetch` with `keepalive` is the only unload-safe send, and MDN (fetched this session) limits its body to **64 KiB**, so only a document that small is sent, with headers from the new `ApiClient.currentHeaders()`; a larger one gets the browser warning only. *Alternative:* the warning only, which keeps "one `ApiClient`" literal; a pending edit is at most 1.5 s old once the warning is accepted. Manual case only for the real tab close.

**3.4 Panels (AC-66).** One `FieldSpec` per field, `table: 'map.<kind>'`, in `models/field_specs/`: **wall** t, kind; **opening** kind, w, at, name, clearW, entrance; **unit** name, category, walkable, passThrough (only while `walkable` is off), `floor.finish`; **floor** name, shortName, spokenName, ordinal, elevation, height, `size.0`, `size.1`, `origin.0`, `origin.1`, `floor.finish`; **Blank start** building `name` and `type` (an `fk` over `building-types` with the code as value) and the floor's fields. Decimals are held as the typed string (`ColKind.decimal`), parsed only when valid; a dragged value is rounded to 0.001 with the rounding vectors in `functions/src/config/venue-map-rounding-vectors.json` (the file OA-1 keeps for this helper). A unit's width, depth and area are read-only text rows, not specs (no document field). Changing a unit's category recomputes `walkable` from `walkableUnitCategory` (**DC-P8**; *alternative:* only when the admin has not set it). A VIEWER's panel builds no input (`asReadOnly`). The Add-floor dialog's building pick (a document's buildings, or "Outdoor ground" while it has none) is a plain choice over the document, not a spec: the lint types a level's `building` as a reference, "picked on the canvas, never a form field".

**3.5 Colours (rule 6, AC-77, AC-136).** The document holds finish keys only. `gabay_tokens.dart` gains `MapFinishTokens`: a light and a dark colour for each of the 6 `FloorFinish` and 10 `ItemFinish` keys, looked up through the enum (a new key without a colour fails a test that walks `.values`). Selection, handles, the grid, the snap marker, the state icons and the review outline come from `colorScheme` or new tokens in that file; no `Color(` elsewhere (`colour-literals`).

**3.6 Registry (AC-142): DESIGN CHOICE DC-P9. 4a-1 flips `map-editor` to `built: true`** and registers the venue list in `built_screens.dart`. *Why:* AC-142 reads "flipped to built", and this slice is the first the owner can open from the menu and use end to end (§1 of the spec's table: "what the owner sees in the browser"); a placeholder would hide a working editor. *Cost:* the menu says built while furniture, connectors, Checks, History and Stores are still missing; accepted, localhost only (E-20). *Alternative:* flip at 4c, when the editor is complete; better if the owner does not want a half editor in the menu. Roles come from the registry's grants (AC-137): VIEWER read-only, VENUE_EDITOR draws without Publish, MALL_ADMIN and SUPERADMIN everything; `editor_access.dart` reads `moduleAccessProvider('map-editor')`.

**3.7 Publish button (AC-74).** `context.go('/admin/publish?venueId=<id>')`: the module placeholder until FF-3′ (the query is ignored now). The editor is left, so coming back is a fresh load (item 7 met by construction; `RefreshOnReturn` also reloads a clean editor under a pushed route).

**3.8 Tenant switch (AC-73, AC-138): DESIGN CHOICE DC-P7.** `ApiClient` sets `X-Tenant-Id` at send time (read in `api_client.dart`), so a save in flight during a switch would go to the new tenant (the server binds its own tenant and answers 404: nothing is written, rule 2). To honour "finish any pending save first", the dev switcher awaits a small provider of flush callbacks before it applies a change; the editor registers one. *Alternative:* accept the loss of at most 1.5 s of unsaved drawing on a dev-only control that R8 deletes; cheaper, and it breaks AC-73's wording.
