## 0. Doc checks pasted into the PR before building (spec §10 RECALLED)

- **(a) `express-rate-limit` 8.7.1** (`functions/node_modules/express-rate-limit/dist/index.cjs`, `index.d.ts`). The planner read these this session; the coder re-reads them and pastes the lines.
  - `standardHeaders: true` resolves to `'draft-6'` (cjs 805-806): `RateLimit-Policy`, `-Limit`, `-Remaining`, `-Reset`. `legacyHeaders: false` drops `X-RateLimit-*`.
  - `Retry-After` is set before `handler` runs, and only when a header family is on (cjs 303, 1052-1060). Its value is `max(0, ceil((resetTime - now)/1000))` (cjs 242-251), so 0 is possible at the very end of a window (DC-41).
  - A hit is counted on entry.
    - With `skipSuccessfulRequests`, the hit is given back only on `finish`, and only while the window has not reset (`decrementKey`, cjs 1001-1050).
    - The `close` listener exists only under `skipFailedRequests` (cjs 914, 1028-1032). So AC-8 needs a give-back of its own (DC-30).
  - `req[requestPropertyName]` is `{ limit, used, remaining, resetTime, key }` (d.ts 533-539).
  - The default store is a new `MemoryStore` for each `rateLimit()` call. `MemoryStore` and `ipKeyGenerator` are exported, and the store has `decrement(key)`.
  - A `logger` option `{ error, warn }` (d.ts 172-181; cjs 788) receives the library's own diagnostics, called pino-style (the console fallback reverses the arguments, cjs 224-231).
- **(b) `zod` 4.6.5.** Source-checked: an absent optional key stays absent in the output (`v4/core/schemas.cjs` 909-915), so `refuseIfDifferent`'s `Object.hasOwn` keeps its meaning for the echo keys. RECALLED, and to be pasted:
  - `z.object` strips unknown keys;
  - the `error` parameter sets a message;
  - `.pipe()` runs its second schema only when the first passes;
  - issues follow the shape's key order;
  - `ctx.addIssue` in a refinement never throws out of `safeParse`;
  - an issue has `code`, `message` and `path`.
- **(c) Node 22 `http.ServerResponse`.** `finish` does not fire when the socket closes first. `close` fires in both cases, after `finish`. `writableFinished` is true only after `finish`. RECALLED; the AC-8 and AC-25 tests settle it.
- **(d) Express 5.2.1.** RECALLED; the AC-6 and AC-19 tests settle it.
  - Inside a mounted router, `req.url` and `req.path` are relative and `req.originalUrl` is not, so the audit takes the path at the slot.
  - What `req.params` holds at `finish`.
  - A hop-count `trust proxy` gives `req.ip` as the address the trusted hop appended.
- **(e) pino 10.4.0.** RECALLED.
  - `log.error({ err }, msg)` writes the stack to the log, not to a response.
  - A bare `Error` as the first argument (how the rate limiter calls `warn`) is logged as `err`.
- **(f) The Fetch standard.** RECALLED: `Retry-After` is not a CORS-safelisted response header, so it must be exposed (AC-3).

## 3. Design choices (the spec's DC-1 to DC-27 apply as written; the plan adds these, each with an alternative)

- **DC-28 The API suite runs with the limiters on, at their upper bounds.** `testConfig` sets `RATE_LIMIT_PER_MIN` and `AUTH_RATE_LIMIT_MAX` to DC-29's bounds after `process.env` and before a test's overrides. SEC-1's suites send far more than 15 bad tokens to one app. *Alternative:* `RATE_LIMIT=off` for the suite, which leaves the real stack untested outside SEC-2's own tests.
- **DC-29 Typo bounds:** 100,000 a minute, 10,000 failures, 1,440 minutes. *Alternative:* about ten times each default, which would refuse a legitimate retune after the pilot measures (PRD §7).
- **DC-30 The auth limiter's abort give-back.** After the limiter passes a request, `res.once('close')` calls `store.decrement(req.authRateLimit.key)` on the limiter's own store when `!res.writableFinished` and the window has not reset (the library's own guard). *Alternative:* a check-then-count store (spec DC-3), which replaces the library's middleware.
- **DC-31 `REDACT_NODE_BUDGET = 2,000`.** The smallest JSON node is about 2 characters, so 2,000 nodes fill the 4,000-character cap; anything past them could not be stored anyway. *Alternative:* 10,000, which does more work per request for the same row.
- **DC-32 The body-free declaration is matched at the slot.** `venueMaps.js` exports `{ method, path template, summarise }` and `createApp` registers it, so a save refused before its route runs (a 401, a tenant 403, a VIEWER's 403) is body-free too. `draftVersion` comes through `res.locals`. AC-21's 403 and 401 cases catch a renamed path. *Alternative:* a route-level middleware, which runs after the guards, so a refused save would fall back to a cut body holding layout text.
- **DC-33 Paging keeps one interpreter.** `pagingQuery` only reduces `page`, `pageSize` and `search` to a string or nothing; `parsePaging` stays the clamp, default and search rule, and `sortBy`/`sortOrder` are stripped because both lists fix their order. *Alternative:* move `parsePaging`'s rules into the schema, which changes `pagination.test.js` and `controlCharacters.test.js` with no change in behaviour.
